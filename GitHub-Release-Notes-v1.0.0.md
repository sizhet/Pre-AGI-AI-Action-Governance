# Release Overview

This is the first public release of **Pre-AGI AI Action Governance**, a research and policy framework for governing consequential autonomous AI action without waiting for Artificial General Intelligence.

The repository begins from a simple observation:

> **High-impact AI does not require AGI.**

A bounded AI model can acquire substantial effective power when combined with:

* autonomous agents,
* persistent looping,
* large-scale search,
* parallel execution,
* memory,
* external tools,
* privileged access,
* and broad operational permissions.

The resulting governance problem is therefore not only:

> **How intelligent is the AI?**

It is increasingly:

> **What authority has the AI been given, what can it do with that authority, at what scale, and who remains accountable for the consequences?**

This release develops a framework for answering that question.

---

# Central Thesis

The foundational principle of this repository is:

> **Intelligence does not imply authority.**

Increasing model capability should not automatically imply increasing operational authority.

Likewise, the absence of AGI should not automatically imply the absence of serious AI risk.

The relevant governance object is increasingly the deployed **AI Action Configuration**:

```text
Model
+
Agent Runtime
+
Tools
+
Permissions
+
Scale
+
Persistence
+
Target Environment
+
Control Structure
```

This leads to a practical shift:

```text
From:

How intelligent is the model?

To:

What can the deployed system autonomously do?
With what authority?
At what scale?
With what consequence?
Under whose responsibility?
```

# Why Pre-AGI Governance?

Much AI safety discussion focuses on a possible future pathway:

```text
More Powerful Models
        ↓
AGI
        ↓
Recursive Self-Improvement
        ↓
Superintelligence
        ↓
Catastrophic Risk
```

This pathway deserves research.

But another pathway is already operationally relevant:

```text
Current / Near-Term AI
        ↓
Agent
        ↓
Tools
        ↓
Looping
        ↓
Massive Parallel Search
        ↓
Permissions
        ↓
External Action
        ↓
Real-World Consequence
```

The second pathway does not require AGI.

This repository focuses on that **Pre-AGI Action Path**.

# The Four Core Problems

Version 1.0.0 organizes the framework around four closely connected problems.

## 1. The Scale-Looping Power Problem

How much effective system power can emerge from bounded intelligence through:

```text
Search
+
Looping
+
Evaluation
+
Memory
+
Parallelism
+
Tools
```

?

Scale Looping can transform ordinary trial-and-error into industrialized machine search.

But:

> **Looping Improvement ≠ Recursive Intelligence Explosion.**

Its power remains bounded by evaluator quality, search-space structure, ground truth, feedback quality, physical constraints, and other factors.

---

## 2. The Pre-AGI Risk Problem

How much real-world consequence can an AI system create before reaching anything reasonably described as AGI?

A key observation is:

> **Scale can compensate for bounded intelligence.**

A system does not need universal intelligence if it can repeatedly search a narrower action space at machine scale.

This creates the possibility of:

```text
Bounded Intelligence
×
Looping
×
Scale
×
Tools
×
Authority
        ↓
High-Impact Autonomous Power
```

---

## 3. The Autonomous Impact Threshold Problem

At what point does an ordinary AI tool become a consequential autonomous system requiring stronger governance?

Version 1.0.0 introduces the **Autonomous Impact Threshold (AIT)**.

AIT evaluates the combination of:

```text
Autonomy
Authority
External Access
Scale
Looping / Persistence
Consequence
Verification / Human Control
```

The framework proposes four practical governance zones:

```text
AIT-0 — Ordinary AI Tool
AIT-1 — Bounded Agent
AIT-2 — Consequential Autonomous System
AIT-3 — High-Impact Autonomous System
```

The key principle is:

> **More autonomous impact requires more structural control.**

---

## 4. The Governance Target Selection Problem

Before regulating AI, policymakers must determine:

> **What exactly is the object being regulated?**

Possible targets include:

```text
Training
Model
Capability
Agent
Tools
Permissions
Authority
Action
Consequence
```

These are not equivalent.

Version 1.0.0 proposes three canonical rules:

> **Model evaluation informs governance.**

> **Action capability triggers governance.**

> **Consequence determines governance intensity.**

This avoids two symmetric errors:

```text
Powerful AI
    ↓
Therefore Restrict Intelligence
```

and:

```text
Not AGI
    ↓
Therefore No Serious Risk
```

# The AI Action Accountability Stack

High-impact autonomy creates a second question:

> **Who remains responsible when an AI agent acts?**

The repository proposes the **AI Action Accountability Stack**.

Its foundational principle is:

> **AI autonomy must not break the chain of accountability.**

The framework distinguishes four major responsibility layers:

```text
Layer 4
Critical-Action Governance
        ↑
Layer 3
Dangerous Capability Enablement
        ↑
Layer 2
Platform Duty of Care
        ↑
Layer 1
Owner / Deployer Responsibility
```

Responsibility should be evaluated using factors including:

```text
Intent
Knowledge
Control
Foreseeability
Material Enablement
Negligence
Recklessness
Safeguards
Response After Discovery
```

AI autonomy itself should not create an accountability vacuum.

# Generator ≠ Evaluator

A recurring concern throughout this release is self-confirming machine loops.

A weak architecture is:

```text
AI Generates
    ↓
AI Evaluates
    ↓
AI Approves
    ↓
AI Executes
```

A stronger architecture separates these functions:

```text
Generator
    ↓
Candidate
    ↓
Independent Evaluation
    ↓
External Evidence
    ↓
Counter-Evidence
    ↓
Policy Gate
    ↓
Execute / Reject / Escalate
```

Therefore:

> **Closed Loop ≠ Correct Loop.**

And:

> **An intelligence loop is only as trustworthy as its verification structure.**

---

# Counter-Evidence

High-impact AI should not only search for evidence supporting an action.

It should also search for evidence against it.

```text
Evidence For
      ↕
Decision
      ↕
Counter-Evidence
```

Counter-evidence can help detect:

* hidden failure,
* self-confirmation,
* reward hacking,
* metric exploitation,
* unsafe optimization,
* unsupported assumptions.

It therefore becomes both a reasoning mechanism and a governance primitive.

---

# Delta Intelligence

As AI-generated work increases, exhaustive human review becomes increasingly difficult.

The framework therefore emphasizes structural change localization.

For AI coding:

```text
Code Delta
    ↓
CallingGraph Delta
    ↓
Dependency Delta
    ↓
State Delta
    ↓
Permission Delta
    ↓
Behavior Delta
    ↓
Security Delta
    ↓
Blast-Radius Delta
```

This shifts review from:

> **Review everything.**

toward:

> **Locate and deeply verify what changed consequentially.**

---

# Human-at-the-Right-Decision-Point

Human oversight does not scale simply by inserting an approval button.

A human reviewing thousands of machine-generated decisions may provide only nominal supervision.

Version 1.0.0 therefore distinguishes:

> **Human-in-the-Loop**

from:

> **Human-at-the-Right-Decision-Point**

A practical structure is:

```text
Routine Action
      ↓
Machine

Uncertain Action
      ↓
Independent Verification

High-Risk Delta
      ↓
Human Review

Critical / Irreversible Action
      ↓
Strong or Multi-Party Authorization
```

Human judgment should be concentrated where it has the highest governance value.

---

# Scale Is a First-Class Governance Variable

Traditional authorization often asks:

```text
Can X perform Y?
```

Autonomous AI requires a richer question:

```text
Can Agent X
perform Action Y
against Target Z
at Rate R
for Duration T
using Resource Budget B
under Policy P?
```

This matters because:

> **One permitted action and one million adaptive repetitions of that action are not operationally equivalent.**

Scale, persistence, and looping therefore belong inside the permission model.

---

# Governance Without Unnecessarily Restricting Intelligence

This repository does not advocate stopping AI development.

It instead proposes separating:

```text
INTELLIGENCE PLANE
```

from:

```text
AUTHORITY / ACCOUNTABILITY CONTROL PLANE
```

The intelligence plane may become increasingly capable.

The control plane determines:

* identity,
* permissions,
* resources,
* targets,
* scale,
* verification,
* escalation,
* interruption,
* accountability.

A core architectural principle is:

> **The intelligence plane should not have unilateral authority to rewrite the accountability control plane.**

---

# Regulatory Neutrality

The framework is intended to apply independently of whether an AI system is:

* open or closed,
* large or small,
* commercial or academic,
* domestic or foreign,
* developed by an incumbent or a new entrant.

The primary question is:

> **What consequential autonomous action can the deployed system perform?**

Comparable autonomous impact should imply comparable governance expectations.

This reduces both regulatory blind spots and unnecessary barriers to beneficial AI development.

# Five Core Principles

Version 1.0.0 establishes five central principles.

### Principle 1

> **Intelligence does not imply authority.**

### Principle 2

> **AI autonomy must not break the chain of accountability.**

### Principle 3

> **Consequential AI action should be identity-bound, permission-bounded, scale-bounded, auditable, and interruptible.**

### Principle 4

> **Model evaluation informs governance; action capability triggers governance; consequence determines governance intensity.**

### Principle 5

> **The stronger the autonomous impact, the stronger the required accountability.**

# Final Perspective

AI may make intelligence increasingly abundant.

That is not necessarily the problem.

The deeper governance problem emerges when abundant intelligence acquires abundant, poorly bounded authority.

Therefore:

> **The greatest early mistake in AI regulation may be governing intelligence when the real governance target is autonomous authority.**

The practical objective is not:

> **Stop AI.**

It is:

> **Bound AI Action.**

The long-term challenge is therefore:

> **How do we make abundant machine intelligence structurally controllable before it acquires abundant machine authority?**

Version 1.0.0 is a first framework toward answering that question.
