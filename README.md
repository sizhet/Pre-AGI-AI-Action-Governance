# Pre-AGI AI Action Governance

## Governing Autonomous Authority, Scale, and Consequential Action Before AGI

> **Do not wait for AGI to govern consequential AI action.**

> **Do not unnecessarily constrain intelligence. Govern autonomous authority, scale, access, and consequence.**

---

## Why This Repository Exists

Much of the current AI governance debate is organized around a future threshold:

```text
More Powerful Models
        ↓
AGI
        ↓
Recursive Self-Improvement
        ↓
Superintelligence
        ↓
Catastrophic Risk
```

That pathway may matter.

But it is not the only pathway that matters.

A much more immediate path is already visible:

```text
Capable AI
    ↓
Agent
    ↓
Loop
    ↓
Tools
    ↓
Scale
    ↓
Permissions
    ↓
External Action
    ↓
Real-World Consequence
```

This second pathway does **not** require AGI.

A bounded model can become operationally powerful when combined with:

* persistent execution,
* large-scale search,
* autonomous looping,
* external tools,
* powerful credentials,
* parallel agents,
* high-impact permissions.

This repository studies that problem.

Its central concern is not:

> **How intelligent is the AI?**

It is:

> **What authority has the AI been given, what can it do with that authority, at what scale, and who remains accountable for the consequences?**

---

# Core Thesis

The foundational principle of this repository is:

> **Intelligence does not imply authority.**

A highly capable AI should not automatically receive broader permissions merely because it is more intelligent.

Likewise, a system should not be considered safe merely because it does not satisfy some definition of AGI.

The real governance object is increasingly the complete deployed action configuration:

```text
Model
+
Agent Runtime
+
Tools
+
Permissions
+
Scale
+
Persistence
+
Target Environment
+
Control Structure
```

We call this the **AI Action Configuration**.

# The Governance Target Selection Problem

Before regulating AI, policymakers must first identify the correct object of regulation.

Possible targets include:

```text
Training
Model
Capability
Agent
Tool Access
Permission
Authority
Action
Consequence
```

These are not equivalent.

The repository therefore adopts three canonical governance principles:

> **Model evaluation informs governance.**

> **Action capability triggers governance.**

> **Consequence determines governance intensity.**

And one deeper structural rule:

> **Authority should never scale automatically with intelligence.**

# Why Pre-AGI Governance Matters

A dangerous AI system does not need to be generally intelligent.

A moderately capable model may become high-impact through:

```text
Loop
×
Scale
×
Tools
×
Persistence
×
Authority
```

This creates a critical distinction:

```text
General Intelligence Threshold
```

is not the same as:

```text
Autonomous Impact Threshold
```

The second may arrive much earlier.

This repository focuses on that earlier transition.

---

# Scale-Looping Power

Modern AI systems increasingly operate through loops:

```text
Generate
   ↓
Execute
   ↓
Observe
   ↓
Evaluate
   ↓
Modify
   ↓
Retry
```

When this structure is multiplied by:

* massive parallelism,
* memory,
* external tools,
* machine-speed execution,
* automated evaluation,

ordinary trial-and-error becomes:

> **Industrialized Search Intelligence**

This can dramatically amplify useful capability.

It can also dramatically amplify:

* error,
* exploitation,
* unsafe experimentation,
* unauthorized action,
* destructive automation.

Scale Looping is therefore both a capability mechanism and a governance problem.

---

# Scale Looping Is Powerful — But Not Magic

Scale Looping should not be confused with guaranteed recursive intelligence explosion.

Its power remains bounded by:

```text
Search-Space Complexity
Evaluator Quality
Ground Truth
Experiment Cost
Feedback Delay
Physical Constraints
Local Optima
Distribution Shift
```

A powerful loop may optimize known objectives extremely well.

That does not prove the system can automatically:

* select the right scientific problem,
* invent fundamentally new representations,
* judge ambiguous long-term outcomes,
* recursively improve intelligence without limit.

Therefore this repository rejects two symmetric mistakes:

```text
Scale Looping is powerful
        ↓
Therefore AGI is imminent
```

and:

```text
Scale Looping is not AGI
        ↓
Therefore it is not dangerous
```

The more accurate conclusion is:

> **Bounded intelligence can become operationally powerful through looping, search, scale, tools, and authority.**

---

# The Autonomous Impact Threshold

The repository defines the **Autonomous Impact Threshold (AIT)** as:

> **The point at which an AI system's combination of autonomy, authority, access, scale, persistence, and consequence becomes large enough that ordinary user-level safeguards are no longer sufficient.**

AIT is not based on:

* model brand,
* parameter count,
* benchmark score,
* whether a system is called AGI,
* whether the developer is large or small.

AIT is based primarily on the **action surface**.

---

# The Seven AIT Dimensions

A practical assessment should examine:

```text
A — Autonomy
P — Permission / Authority
E — External Action
S — Scale / Parallelism
L — Looping / Persistence
C — Consequence / Reversibility
V — Verification / Human Control
```

These dimensions describe what the deployed system can actually do.

---

# Four AIT Governance Zones

A useful operational classification is:

```text
AIT-0 — Ordinary AI Tool

AIT-1 — Bounded Agent

AIT-2 — Consequential Autonomous System

AIT-3 — High-Impact Autonomous System
```

### AIT-0

Examples:

* chatbot,
* document summarizer,
* offline analysis,
* local coding assistant.

Typical governance:

> Light-touch.

### AIT-1

Examples:

* sandbox coding agent,
* bounded research agent,
* test-generation agent,
* internal workflow bot.

Typical governance:

> Identity, task boundary, permissions, audit.

### AIT-2

Examples:

* production deployment agent,
* customer-facing operational agent,
* financial workflow agent,
* infrastructure management agent.

Typical governance:

> Stronger verification, detailed audit, rate limits, escalation, kill mechanisms.

### AIT-3

Examples:

* critical infrastructure control,
* large financial authority,
* autonomous agent swarms,
* safety-critical systems.

Typical governance:

> Strict authorization, independent verification, continuous monitoring, strong accountability, emergency shutdown.

---

# AIT Is Deployment-Specific

The same model may occupy different governance classes.

```text
Model X
  │
  ├── Offline Chat
  │      → AIT-0
  │
  ├── Sandbox Coding
  │      → AIT-1
  │
  ├── Production Deployment Agent
  │      → AIT-2
  │
  └── Critical Infrastructure Controller
         → AIT-3
```

This is why model-only regulation is insufficient.

> **Risk belongs to the model-runtime-permission-action configuration, not merely to the model.**

---

# AIT Is Dynamic

An AI system can move across AIT levels without any model retraining.

Changes such as:

```text
New Credential
New Tool
More Agents
Higher Rate
Persistent Runtime
New Target
Reduced Verification
Expanded Permission
```

may change the governance class immediately.

AIT should therefore be treated partly as a runtime property.

---

# The AI Action Accountability Stack

Once an AI system becomes consequential, responsibility must remain traceable.

The central principle is:

> **AI autonomy must not break the chain of accountability.**

The repository proposes four major responsibility layers.

```text
┌────────────────────────────────────┐
│ Layer 4: Critical-Action Governance│
├────────────────────────────────────┤
│ Layer 3: Dangerous Enablement      │
├────────────────────────────────────┤
│ Layer 2: Platform Duty of Care     │
├────────────────────────────────────┤
│ Layer 1: Owner / Deployer          │
└────────────────────────────────────┘
```

---

# Layer 1 — Owner / Deployer Responsibility

Deploying an autonomous agent should not transfer responsibility to the agent.

Every high-impact autonomous system should have an identifiable responsible principal.

```text
Responsible Principal
        ↓
Authorized Agent
        ↓
Authorized Scope
        ↓
Action
        ↓
Outcome
```

---

# Layer 2 — Platform Duty of Care

Platforms should not automatically be liable for everything users do.

But platforms that materially enable high-risk autonomous action should exercise reasonable duty of care.

Possible controls include:

```text
Identity
Permission Boundaries
Rate Limits
Sandboxing
Logging
Abuse Detection
Incident Response
Kill Controls
```

Responsibility should increase when a provider:

* knows of dangerous activity,
* reasonably should detect it,
* has practical means to limit it,
* and continues enabling it.

---

# Layer 3 — Dangerous Capability Enablement

General-purpose technology should not be automatically criminalized.

Responsibility should instead depend on factors such as:

```text
Intent
Knowledge
Control
Foreseeability
Material Enablement
Safeguard Removal
Operational Assistance
```

The framework distinguishes:

```text
General-Purpose Capability
        ↓
Known Risk + Safeguards
        ↓
Known Risk + Safeguards Removed
        ↓
Purpose-Built Harmful Capability
        ↓
Knowing Assistance to Specific Harm
```

Responsibility increases along this path.

---

# Layer 4 — Critical-Action Governance

Certain action classes deserve strong controls regardless of model identity.

Examples may include high-consequence operations involving:

```text
Critical Infrastructure
Large Financial Authority
Dangerous Biological Workflows
Weapons Systems
Mass Unauthorized Cyber Activity
Irreversible Production Operations
```

The key principle is:

> **Critical actions should be governed by action class, not by AGI label.**

---

# Accountability-by-Design

Accountability should be embedded in system architecture.

A high-impact system should answer:

```text
Who owns this agent?

What is its identity?

What can it access?

What can it modify?

At what rate can it act?

How long can it continue?

What evaluator governs it?

What evidence can stop it?

Who can interrupt it?

What is logged?

Who is responsible if controls fail?
```

If these questions cannot be answered, the system is under-governed.

---

# Verification Before Authority

A recurring failure mode is:

```text
AI Generates
    ↓
Same AI Evaluates
    ↓
Same AI Approves
    ↓
Execute
```

A stronger structure is:

```text
Generator
    ↓
Candidate
    ↓
Independent Evaluator
    ↓
External Evidence
    ↓
Counter-Evidence
    ↓
Policy Gate
    ↓
Execute / Reject / Escalate
```

This yields another core principle:

> **Generation should not automatically confer verification authority.**

---

# Counter-Evidence as a Governance Primitive

High-impact systems should not merely search for reasons to act.

They should also search for reasons **not** to act.

```text
Evidence For
      ↕
Decision
      ↕
Evidence Against
```

This helps resist:

* self-confirmation,
* reward hacking,
* metric exploitation,
* over-optimization,
* hidden failure.

Counter-evidence is therefore not merely a reasoning technique.

It can become part of the control plane.

---

# Delta Intelligence

As AI generates more code, plans, workflows, and system changes, universal line-by-line review becomes increasingly impractical.

The governance system must instead ask:

> **What changed structurally?**

For software:

```text
Code Delta
   ↓
CallingGraph Delta
   ↓
Dependency Delta
   ↓
State Delta
   ↓
Permission Delta
   ↓
Behavior Delta
   ↓
Security Delta
   ↓
Blast-Radius Delta
```

This supports **localized review of consequential change**.

---

# Human-at-the-Right-Decision-Point

“Human-in-the-loop” is not sufficient if humans are overwhelmed.

```text
50,000 AI Decisions
        ↓
Human Clicks Approve
```

is not meaningful governance.

A better architecture is:

```text
Routine Low-Risk Action
        ↓
Machine

Ambiguous Action
        ↓
Verification

High-Risk Delta
        ↓
Human Review

Critical Action
        ↓
Multi-Party Authorization
```

The objective is:

> **Human-at-the-Right-Decision-Point.**

---

# Scale Is a First-Class Governance Variable

Traditional systems often ask:

> Can X perform Y?

AI governance must increasingly ask:

```text
Can Agent X
perform Action Y
against Target Z
at Rate R
for Duration T
using Resource Budget B?
```

One action and one million adaptive actions are not equivalent.

Therefore governance must include:

```text
Action
Target
Rate
Duration
Attempt Count
Compute Budget
External Reach
```

---

# Loop Governance

Persistent autonomous loops should have explicit bounds.

A governed loop should define:

```text
Objective
Search Domain
Tool Set
Target Set
Attempt Budget
Compute Budget
Evaluator
Counter-Evidence Rules
Escalation Conditions
Stop Conditions
Audit Requirements
```

The central rule is:

> **No high-impact persistent loop without a policy-governed stopping structure.**

# What This Repository Does Not Claim

This repository does **not** claim that:

* AGI risk is impossible,
* superintelligence should be ignored,
* model safety does not matter,
* capability evaluation is unnecessary,
* AI development should be completely unregulated.

It makes a narrower and more practical claim:

> **Strong operational governance should track actual autonomous impact rather than relying primarily on speculative intelligence labels.**

# Innovation and Safety Are Not Opposites

A well-designed governance framework should allow:

```text
Open Research
Open Models
AI Coding
Scientific AI
Brain Units
Local AI
Small Developers
```

while strongly controlling:

```text
Unbounded Autonomous Authority
Mass Unauthorized External Action
Irreversible High-Impact Operations
Unsafe Persistent Agent Swarms
Critical-System Actions Without Accountability
```

The objective is not:

> **Stop AI.**

It is:

> **Bound AI Action.**

---

# Regulatory Neutrality

Governance should not depend primarily on:

```text
Big Company vs Small Company
Closed Model vs Open Model
US Model vs Foreign Model
Prestigious Frontier Lab vs New Entrant
```

Instead:

> **Same consequential autonomous action → comparable governance expectations.**

This helps reduce both under-regulation and regulatory capture.

---

# Motive-Independent Governance

The framework does not require determining whether AI companies, governments, or executives are:

* sincere,
* commercially motivated,
* strategically motivated,
* excessively optimistic,
* excessively pessimistic.

Those motives may be mixed.

A robust governance framework should work anyway.

The operational questions remain:

```text
What can the AI do?

With what authority?

At what scale?

Against which targets?

Under which controls?

Who is accountable?
```

---

# International Coordination

Countries may disagree about:

```text
What is AGI?
How much compute is too much?
How powerful may models become?
```

But they may find more practical agreement around:

```text
Which autonomous actions are prohibited?

Which critical actions require authorization?

Which systems require attribution?

Which incidents must be reported?

Who is responsible for cross-border AI action?
```

Action-based governance may therefore provide a more practical basis for international coordination than AGI definitions alone.

# Five Core Principles

The repository can be summarized in five principles.

## Principle 1

> **Intelligence does not imply authority.**

## Principle 2

> **AI autonomy must not break the chain of accountability.**

## Principle 3

> **Consequential AI action should be identity-bound, permission-bounded, scale-bounded, auditable, and interruptible.**

## Principle 4

> **Model evaluation informs governance; action capability triggers governance; consequence determines governance intensity.**

## Principle 5

> **The stronger the autonomous impact, the stronger the required accountability.**

# Five Operational Rules

For high-impact AI:

> **No owner → no high-impact agent.**

> **No bounded permission → no high-impact authority.**

> **No independent verification → no irreversible action.**

> **No stop mechanism → no persistent critical loop.**

> **No audit → no high-risk autonomy.**

These rules are intentionally simple.

They can be understood by:

* engineers,
* executives,
* regulators,
* legal professionals,
* platform operators,
* researchers.

# A Practical Governance Checklist

Before deploying a consequential autonomous AI system, ask:

1. Who owns the action?
2. Which identifiable agent performs it?
3. Who authorized the agent?
4. What is the authorized objective?
5. What systems can it access?
6. What can it modify?
7. At what rate can it act?
8. How long can it continue?
9. How many sub-agents can it create?
10. What is the maximum credible blast radius?
11. What evaluator determines success?
12. Is verification independent?
13. Is counter-evidence actively searched?
14. What changes require human escalation?
15. What is the stop condition?
16. Can permissions be revoked immediately?
17. Can actions be rolled back?
18. Is the audit trace reliable?
19. Can the agent alter its own control plane?
20. Who remains legally accountable?

If these questions cannot be answered, the system may not be ready for high-impact autonomy.

# The Larger Vision

AI may make intelligence abundant.

That should be welcomed.

Future societies may contain:

```text
Coding Intelligence
Scientific Intelligence
Engineering Intelligence
Educational Intelligence
Medical Intelligence
Personal Brain Units
Collective Machine Intelligence
```

The challenge is not to keep intelligence scarce.

The challenge is to keep **authority governed**.

This repository therefore imagines a future in which:

```text
More Intelligence
        ↓
More Human Capability
```

without automatically producing:

```text
More Intelligence
        ↓
More Unbounded Authority
```

The two should remain separate.

# The Central Policy Warning

The greatest early mistake in AI regulation may be:

> **Governing intelligence when the real governance target is autonomous authority.**

If the target is chosen incorrectly, society may achieve the worst of both worlds:

```text
Beneficial AI Research
        ↓
Restricted
```

while:

```text
Dangerous Agentic Deployment
        ↓
Insufficiently Controlled
```

Good governance should avoid both.

# Final Perspective

The central AI governance question of the next several years may not be:

> **When will AGI arrive?**

A more immediate question is:

> **When does machine intelligence acquire enough autonomous authority to produce consequential real-world action?**

And once it does:

> **How do we keep that authority bounded, verifiable, interruptible, and accountable?**

That is the problem addressed by **Pre-AGI AI Action Governance**.

The objective is not to stop intelligence from advancing.

It is to prevent intelligence from silently acquiring unbounded authority.

> **Develop intelligence. Govern authority.**

> **Enable beneficial AI. Bound consequential action.**

> **Do not wait for AGI.**
